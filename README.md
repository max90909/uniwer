# Ведомость

Образовательная платформа: 9-месячный курс, несколько групп, числовая система оценивания.
Этот репозиторий — рабочий пример из проектного документа, сейчас на демо-данных: 3 группы
по 25 учеников, полный набор недель/тестов/посещаемости/поведения за весь курс.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который покажет терминал (обычно http://localhost:5173). На экране входа выберите,
от чьего имени смотреть систему — администратора, одного из трёх преподавателей или ученика одной
из групп A/B/C. Настоящего входа по паролю пока нет (см. `supabase/README.md` — это отдельный, поздний этап).

## Что уже работает

- **Ученик** — главная страница со сводкой, материалы (книги/файлы, с demo-скачиванием), полная история
  результатов, прогресс по месяцам (график с плавной кривой и заливкой), место в группе и среди всех
  учеников, посещаемость и журнал поведения.
- **Преподаватель** — список групп и учеников, экран «Внести оценки» (ключевой еженедельный экран —
  ведомость на группу целиком), добавление книг на неделю, отметка посещаемости, журнал поведения,
  рейтинги, статистика группы по месяцам и темам.
- **Администратор** — все пользователи; создание новых групп и добавление списков учеников (просто
  вставить ФИО построчно); расписание недель с возможностью перенести урок (меняются даты недели —
  привязанные тест и книги сдвигаются вместе с ней); настройка весов формул (средний балл, общий индекс)
  и переключатели «учитывать посещаемость/поведение в индексе»; общий рейтинг групп.
- **Оформление** — неоморфизм (мягкий UI на одном фоне, без рамок, только тени).
- **Языки** — русский, English, Türkmen; переключатель — в верхнем углу экрана входа и в боковом меню
  внутри системы. Выбор сохраняется в браузере.

## Как перенести или сдвинуть урок

Администратор → «Расписание» → у нужной недели меняете дату начала/конца и жмёте «Перенести».
Всё, что привязано к этой неделе — тест (weekly/control/final), книги, материалы — автоматически
получает новые даты. Это осознанно сделано на уровне недели целиком (а не отдельного урока/дня),
потому что в текущей модели неделя = один тест + одна порция материалов, и переносить их по
отдельности только усложнило бы интерфейс без реальной пользы.

Все формулы — из раздела 07/08 проектного документа, реализованы как чистые функции в `src/lib/formulas.ts`.
Демо-данные генерируются один раз в `src/data/seed.ts` и дальше редактируются прямо в браузере
(изменения сохраняются в localStorage — можно спокойно вносить оценки, ничего не потеряется при обновлении страницы).

## Как заменить демо-группы на настоящие

1. Администратор → «Формулы и настройки» → «Сбросить демо-данные» очищает текущий набор.
2. До появления реального backend'а самый быстрый способ завести настоящих людей — отредактировать
   стартовые данные прямо в `src/data/seed.ts` (списки ФИО, число групп/учеников, даты курса) и перезапустить `npm run dev`.
3. Когда понадобится реальный вход по email и постоянное хранилище на сервере — см. `supabase/README.md`
   и раздел 11/12 проектного документа: там уже расписана схема (`supabase/migrations`) и что именно менять в коде.

## Структура проекта

```
src/
  types.ts          — доменная модель (соответствует таблицам в supabase/migrations)
  data/seed.ts       — генератор демо-данных (3 группы × 25 учеников, 9 месяцев)
  data/store.tsx     — хранилище + мутации (внести оценки, отметить посещаемость, ...)
  lib/formulas.ts    — все формулы оценивания, рейтингов и статистики
  lib/session.tsx    — демо-сессия (кто сейчас «вошёл»)
  components/        — переиспользуемые UI-блоки (карточки, таблицы, график, шапка навигации)
  pages/student/...  — экраны ученика
  pages/teacher/...  — экраны преподавателя
  pages/admin/...    — экраны администратора
supabase/
  migrations/        — SQL-схема и RLS-политики для настоящего backend'а
```

## Публикация на GitHub Pages (бесплатно, доступ по ссылке из интернета)

В репозитории уже лежит `.github/workflows/deploy.yml` — он сам собирает и публикует сайт
при каждом push в ветку `main`. Нужно один раз:

1. Создать пустой репозиторий на github.com (без README/.gitignore — они уже есть здесь), например `uniwer`.
2. В папке проекта на своём компьютере:
   ```bash
   git remote add origin https://github.com/<ваш-логин>/uniwer.git
   git branch -M main
   git push -u origin main
   ```
3. На странице репозитория: **Settings → Pages → Build and deployment → Source** → выбрать **GitHub Actions**.
4. Открыть вкладку **Actions** — через 1–2 минуты сборка завершится, и сайт появится по адресу
   `https://<ваш-логин>.github.io/uniwer/`.

Дальше просто: любой `git push` в `main` автоматически пересобирает и обновляет сайт.
